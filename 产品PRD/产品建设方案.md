# AI 图纸拆解平台 — 产品建设方案

> 依据《AI 图纸分析与零部件拆解生成平台产品化 PRD V1.0》制定。
> 目标:把当前已验证的核心能力(图解析→IR→校验→拆解→几何生成),建设成
> **可售卖、可交付、可运维、可迭代的企业级工程工作台**。

---

## 1. 现状评估:原型 vs PRD

当前原型(`backend/` + `frontend/`)已经跑通 PRD 中 **P0 核心能力的一条主链路**:
`上传(图+补充说明+佐证文件) → Claude 解析为结构化 IR → 自校验重估置信度 → 拆解推荐 → CadQuery 确定性生成 B-rep/STEP/STL → three.js 3D 预览`。

按 PRD 功能模块逐项对照(✅已具备 / 🟡部分 / ❌缺失):

| PRD 模块 | 子能力 | 现状 | 说明 / 复用点 |
|---|---|---|---|
| 6.1 项目与资料包 | 项目创建/资料上传 | 🟡 | 有 `store.create_project` + 单图 + 附件,但无客户/行业/交期/保密等字段 |
| | 资料自动分类/完整性检查/版本/权限 | ❌ | 全缺 |
| 6.2 2D 解析工作台 | 2D 图纸解析 | ✅ | `vision.parse_drawing`(Claude 多模态)→ 视图/尺寸/特征 |
| | 解析结果可视化(原图高亮) | 🟡 | 前端有拆解树+原图,但无 bbox 叠加高亮(IR 已含 `provenance.bbox`,前端未画) |
| | 人工标注修正(框选/拆分/合并) | ❌ | 现仅能"重新解析",无交互式编辑 |
| | 3D 模型解析(STEP) | ❌ | 只生成 3D,未解析输入 3D |
| | 多视图关联 / 解析任务队列 | ❌ | 同步执行,无队列 |
| 6.3 拆解与 BOM | 结构树 | 🟡 | 当前是**扁平零件列表**,无 设备-总成-部件-零件 层级 |
| | 拆解置信度 + 来源证据 | ✅ | `confidence` + `provenance` + `open_questions` |
| | 零件类型识别 / 标准件匹配 | 🟡 | LLM 会猜标准件规格,但**无标准件库**比对 |
| | BOM 自动生成 / 相似件复用 | ❌ | 无正式 BOM 对象、无导出、无历史库 RAG |
| 6.4 图纸与 3D 生成 | 参数化模型 / 3D 视图 | ✅ | `geometry.py`(CadQuery/OCCT)→ STEP + STL + 质量属性 + 基础校验 |
| | 2D 零件图 / 三视图 / 尺寸标注 | ❌ | **关键缺口**:无 2D 工程图(需 FreeCAD TechDraw) |
| | 导出 DXF/DWG/PDF/BOM Excel | 🟡 | 仅 STEP/STL,缺 2D 与 BOM 导出 |
| | 爆炸图 / 装配预览 / 图纸模板 | ❌ | 无装配、无标题栏模板 |
| 6.5 校核/审签/版本 | 确认/驳回/批注/审签/版本对比/审计 | ❌ | 仅有 `stages` 时间戳,无审批流、批注、审计日志 |
| 6.6 工艺/报价/排产 | 全部 | ❌ | P1/P2,未启动 |
| 6.7 知识库/规则/配置中心 | 全部 | ❌ | P1,未启动 |
| NFR | 多租户/权限/异步/私有化/可配置 | ❌ | 单进程、单用户、文件存储,无鉴权 |

**结论**:原型 ≈ PRD 路线图 **V0.5 核心验证版的一个切片**。距离 V1.0 产品闭环,主要差:
① 工程化底座(DB / 对象存储 / 异步队列 / 鉴权 / 审计);
② 项目与资料包闭环;③ 2D 工程图生成;④ 人工校核与版本控制;⑤ 交互式解析工作台。

## 2. 目标技术架构

从"单进程原型"演进为"服务化企业平台"。分层 + 关键服务拆分:

```
┌────────────────────────────────────────────────────────────────┐
│  前端 SPA (React+TS)  项目中心/解析/拆解/生成/工艺报价/知识库/配置  │
└───────────────┬────────────────────────────────────────────────┘
                │ HTTPS (BFF / API Gateway, JWT+RBAC+租户隔离)
┌───────────────▼────────────────────────────────────────────────┐
│                     应用服务层 (FastAPI)                          │
│  Project | InputPackage | Drawing | Decompose | Generation       │
│  Review/Approval | Knowledge | Config | Audit                    │
└───┬──────────────┬───────────────┬────────────────┬─────────────┘
    │ 任务入队       │               │                │
┌───▼──────┐  ┌─────▼──────┐  ┌─────▼───────┐  ┌─────▼──────────┐
│ AI 编排   │  │ CAD 内核    │  │ 3D/CAD 导入  │  │ 评测/质量       │
│ worker   │  │ worker      │  │ worker       │  │ worker          │
│ (Claude) │  │(CadQuery/   │  │(OCCT STEP    │  │(指标/评测集)    │
│          │  │ FreeCAD     │  │ 解析)        │  │                 │
│          │  │ TechDraw)   │  │              │  │                 │
└───┬──────┘  └─────┬──────┘  └─────┬───────┘  └─────┬──────────┘
    └──────────────┴───── Celery/Redis 任务队列 ─────┴────────────┘
                                │
┌───────────────────────────────▼────────────────────────────────┐
│  数据层: PostgreSQL(业务对象/IR/版本/审计) · MinIO/S3(文件/几何)  │
│         Qdrant(相似件/历史图纸向量) · Redis(队列/缓存)            │
└──────────────────────────────────────────────────────────────────┘
```

设计要点:
- **AI 与 CAD 重依赖隔离成独立 worker**:CadQuery/FreeCAD/OCCT 依赖重(本项目已踩过 OCP 安装坑),与业务服务解耦,可单独扩缩容、私有化时单独打镜像。
- **异步任务队列**(PRD 6.2/NFR 性能要求):解析、生成、3D 导入都改为入队 + 进度/重试/日志,满足"2D<60s、STEP<5min、批量异步"。
- **可配置**(PRD 6.7/NFR):模型、Prompt、阈值、规则、模板、审批流均落到 **配置中心** 表,支持版本发布/回滚。
- **可追溯**(PRD NFR):每个 AI 产出记录 模型版本 + Prompt 版本 + 输入文件版本 + 时间 + 人工修改记录 —— 当前 `store.py` 的"证据链"思路升级到 DB。

## 3. 数据模型:从 DesignIR 扩展到 PRD 对象模型

当前 `models/ir.py` 的 `DesignIR/Part/Feature` 是很好的内核,**保留作为"几何意图 IR"**,外面包一层 PRD 的业务对象关系模型(PostgreSQL):

| PRD 对象 | 来源 | 落地方式 |
|---|---|---|
| Project | 新建 | 表:客户/行业/类型/数量/交期/负责人/保密等级/状态 |
| InputPackage / File | 扩展现 attachments | 表:文件/版本/来源/资料类型/完整性状态;文件入 MinIO |
| Drawing | 现 source 图 | 表:格式/页码/视图类型/比例/解析状态 |
| Model(3D) | 新建(STEP 导入) | 表:格式/装配层级/体积/质量属性 |
| Equipment | 现 `DesignIR.device_name/intent` | 表:结构树根节点 |
| Assembly | **新增层级**(现为扁平) | 表:父子装配关系(树) |
| Part | 现 `DesignIR.parts[]` | 表 + 内嵌 `features`(JSONB,即现 Feature) |
| Feature | 现 `Feature` | 存 Part.features JSONB(几何生成依据) |
| BOM | 由 parts+standard_parts 派生 | 表:层级/数量/材料/图号/版本/外购标识 + Excel 导出 |
| ProcessRoute | 新建(P2) | 表:工序/设备/工时/外协/检测 |

> 迁移策略:`DesignIR` 继续作为"单设备一次解析的结构化结果"在解析/生成服务内部流转;
> 保存时拆写进 Equipment/Assembly/Part/BOM 关系表,实现层级结构树、版本与 BOM 导出。
> **需要把现"扁平 parts"升级为可含 assembly 层级的树**(PRD 6.3 P0)。

## 4. 分阶段路线图(对齐 PRD V0.5→V3.0)

每个版本给出:目标、关键交付、对现有代码的复用/改造。

### V0.5 核心验证版(补全)— 已基本具备,补两块
- **复用**:现解析/校验/拆解/CadQuery 生成/3D 预览全部保留。
- **补 ① 2D 工程图生成**:接入 **FreeCAD(headless)TechDraw**,从 STEP 自动投影 三视图 + 剖视 + 尺寸标注,导出 DXF/PDF(PRD 6.4 P0,当前最大缺口)。
- **补 ② 3D STEP 导入解析**:用 OCCT 读取客户 STEP,抽装配层级/体积/包围盒/孔槽特征 → 反向生成 IR(PRD 6.2 P0)。
- 退出标准:单设备从"2D 或 3D 输入"都能跑到"零件图 + BOM 草稿 + 3D 预览"。

### V1.0 产品闭环版(首个企业试点)— **本方案重心**
工程化底座 + 项目闭环 + 人工校核。具体:
1. **工程化底座**:PostgreSQL + MinIO + Redis/Celery + JWT/RBAC + 审计日志表;现 `store.py` 文件存储迁移到 DB+对象存储。
2. **项目中心 + 资料包中心**(6.1):项目 CRUD、批量上传、资料自动分类(用 Claude 判别 工程图/装配图/BOM/规格书)、完整性检查(缺材料/数量/交期提示)。
3. **解析工作台**(6.2):原图 + `provenance.bbox` 叠加高亮、低置信度区域标红、框选/拆分/合并/改名/补尺寸的**交互式人工修正**(改 IR → 局部重生)。
4. **拆解工作台**(6.3):**层级结构树**(设备-总成-零件)、BOM 表格、零件属性编辑。
5. **生成工作台**(6.4):参数修改 → 重新生成 → 版本对比 → 导出(PDF/DXF/STEP/STL/Excel)闭环。
6. **人工校核与版本**(6.5):校核任务、批注/问题单、确认/驳回/重生、版本快照与对比、操作审计。
- 退出标准:命中 PRD 第 12 章验收(项目管理/解析/拆解/生成/校核/导出/审计全绿)。

### V1.5 工程增强版(试点深化)
- **知识库**(6.7):历史图纸库、标准件库、材料库、工艺规则库。
- **相似件复用**(6.3):Qdrant 向量检索,拆解/生成时提示"复用 vs 新建"。
- **图纸模板**(6.4):企业标题栏/图号规则/签审栏模板。版本差异对比增强。
- **规则校验**:工艺规则库驱动 DFM(孔边距/折弯半径/洁净/真空/耐压),升级现 `geometry.py` 的内置校验。

### V2.0 报价衔接版
- 工艺分类 + 工艺路线建议 + 成本要素 + 报价模板(6.6 P1/P2)。

### V2.5 排产衔接版
- 工时估算、资源/外协/交期约束输出,供 MES/ERP 消费(6.6 P2)。

### V3.0 平台商业版
- 多租户、细粒度权限、接口集成(PLM/ERP/MES/CAD 插件)、模型评测中心、运维后台、私有化部署包。

## 5. 技术选型演进(原型 → 产品)

| 维度 | 原型现状 | 产品目标 | 迁移动作 |
|---|---|---|---|
| 存储 | `store.py` 文件 + JSON | PostgreSQL + MinIO/S3 | SQLAlchemy + Alembic;文件入对象存储 |
| 任务 | 同步 HTTP | Celery + Redis(或 Temporal) | 解析/生成/导入改为入队 + 状态轮询/WebSocket |
| AI | `claude_client.py` 直连 | AI 编排服务 + Prompt/模型/阈值配置 + 版本与评测 | 抽 Prompt 到配置中心;记录模型/Prompt 版本 |
| CAD | `geometry.py`(CadQuery) | CAD worker:CadQuery 建模 + FreeCAD TechDraw 2D + OCCT STEP 导入 | 独立服务/镜像;加 2D 投影与 3D 解析 |
| 鉴权 | 无 | OIDC/JWT + RBAC + 租户隔离 | 网关层统一,接企业 SSO |
| 前端 | 单 `index.html` | React+TS SPA,7 大导航工作台 | 渐进重写;three.js 预览复用 |
| 可观测 | print | 结构化日志 + Prometheus + 审计表 + 任务看板 | 落 NFR 可追溯/审计 |
| 部署 | 本机 uvicorn | Docker Compose → K8s,私有化包 | 业务/AI/CAD 分镜像,GPU 可选 |

## 6. 非功能与工程化(PRD 第 8 章)

- **性能**:2D<60s、STEP<5min、批量异步队列 → 靠 worker 拆分 + 队列 + 结果分步落库。
- **稳定性**:解析失败可重试、任务异常不中断项目、结果分步保存 → 任务状态机 + 幂等 + 断点续存。
- **安全**:项目级权限、下载权限、导出水印、操作审计、数据隔离 → 网关 RBAC + 审计表 + PDF 水印。
- **可追溯**:AI 输出记录 模型版本/Prompt 版本/输入文件版本/时间/人工修改 → 贯穿所有产出对象。
- **可配置/可部署/可扩展**:配置中心 + 私有化镜像 + PLM/ERP/MES 集成接口预留。

---

## 7. 质量度量与评测(PRD 第 9 章)

建评测闭环(V1.5 起持续):
- **评测集**:积累带人工标注答案的 2D/3D 图纸样本集。
- **指标**:视图识别准确率、尺寸抽取准确率、零件召回率、错拆率、图纸一次通过率、平均解析时长、人工修改工时节省率、相似件复用率、任务失败率。
- **反馈闭环**:人工校核的每次"修改/驳回"回流为评测样本,驱动 Prompt/阈值优化(配置中心可灰度发布、回滚)。

## 8. 主要风险与应对(PRD 第 13 章,已内建于架构)

| 风险 | 应对(已体现在方案) |
|---|---|
| 图纸输入质量差 | 资料完整性检查 + 低置信度提示 + 人工补充(现 `open_questions` + 自校验已奠基) |
| AI 生成图纸不可制造 | **坚持 CAD 内核/参数化脚本生成 + 人工审签**(本平台核心原则,已落地) |
| 行业规则复杂 | 规则库模板化,按行业/客户配置(配置中心) |
| 3D 解析难 | 先支持 STEP 装配层级 + 基础特征,复杂件人工确认 |
| 客户期望过高 | 明确"AI 辅助 + 人工校核"边界,UI 上始终给置信度/风险提示 |
| 数据安全 | 私有化部署 + 项目隔离 + 权限 + 日志 + 水印 |

## 9. 立即可执行(未来 2–4 周,衔接原型→V1.0)

按 PRD 第 14 章"建设顺序",从复用最大、价值最高处切入:

1. **【最高优先·补 P0 缺口】2D 工程图生成**:CAD worker 接 FreeCAD TechDraw,从现有 STEP 自动出三视图+标注+DXF/PDF。这是 PRD 6.4 P0 当前唯一硬缺口,补上即形成"3D+2D"完整生成。
2. **【底座】引入 PostgreSQL + 对象存储**:把 `store.py` 抽象为仓储接口,先用 SQLite/Postgres 落 Project/Part/BOM,文件进 MinIO。为版本/审计/多用户铺路。
3. **【闭环】异步任务队列**:解析/生成改造为 Celery 任务 + 状态查询,前端加进度。
4. **【结构】扁平 parts → 层级结构树**:扩 IR 支持 assembly 层级 + BOM 对象 + Excel 导出。
5. **【交互】解析工作台 v1**:前端用 `provenance.bbox` 在原图上叠加高亮 + 低置信标红 + 行内编辑 IR 参数后局部重生。

## 10. 需你确认的关键决策

下列选择会影响建设排序,确认后细化里程碑与排期:

1. **首要交付形态**:私有化/本地部署优先(高端制造客户常要求内网)还是 SaaS 多租户优先?
2. **试点客户/行业**:先聚焦哪个行业规则(半导体洁净/真空、电子结构件、能源耐压)做 MVP 规则库?
3. **零件类型 MVP 范围**:是否按 PRD 第 11 章先锁定 钣金板件/安装板/支架/型材/简单机加件?
4. **团队与时间**:可投入的研发人力与期望的 V1.0 试点时间点?(决定并行度与外包/采购取舍)
5. **2D CAD 依赖**:是否接受引入 FreeCAD(LGPL,可商用)作为 2D 工程图引擎?
```
